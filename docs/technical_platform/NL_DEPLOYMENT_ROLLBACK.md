# GitHub、Zeabur 与客户端更新回退手册

## 服务端发布

1. 仅从 `main` 的已验证提交构建。
2. 先等待 GitHub 客户端、服务端和镜像任务通过。
3. Zeabur 执行 Alembic 到仓库当前 head，再启动应用。
4. 核对 `/health`、`/api/v1/capabilities` 的 40 位构建 SHA 与 GitHub 提交完全一致。
5. 失败时回退到上一已验证镜像；数据库只按经审查的向下迁移方案处理，不直接删除新表或审计记录。

## 客户端发布

1. GitHub Release 的版本、文件名和资产内容不可覆盖；修复必须使用新版本号和新序号。
2. 总控仅登记由内置可信密钥可复验的签名清单，先草稿，再灰度，最后稳定。
3. 客户端先下载到非系统盘暂存区，复验 URL、签名、大小和 SHA256，再等待当前客户端退出。
4. 独立更新器备份全部项目数据库，候选 EXE 健康检查通过且数据库指纹未变化才切换。
5. 候选启动失败时保留旧版本；若已经进入切换阶段则进入 `recovery_required`，只有确认业务数据库未变化时才自动恢复旧版本选择。
6. 若业务数据库已有新写入，禁止自动覆盖，保留备份和失败版本供人工恢复。

## 0.2.7 特别说明

0.2.7 是首个数据架构 11 的托管更新基线。0.2.6 及更早版本必须使用 `ZQ-Workspace-0.2.7-Managed-Windows.zip` 接管一次；接管包只改变程序布局，不搬移或覆盖业务项目。后续版本从托管启动器进入在线更新。
