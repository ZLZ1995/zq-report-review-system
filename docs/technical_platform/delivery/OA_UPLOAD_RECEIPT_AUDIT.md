## 2. 已确认行为与风险

1. 文件选择change回调直接执行上传；auto-upload=false不代表没有自动服务器写入，它只关闭组件自身默认上传。按钮“提交审核”是后续独立动作，测试不得触发。
2. 待审资料包分类为REPORT_ZIP，阶段由审核轮次生成。后端上传会将同工单、分类、阶段的已有当前版本置为非当前，再创建新版本。不得把它描述成无影响的附件追加。
3. POST /files/upload在db.commit后返回附件记录，含id、work_order_id、file_category、business_stage、version_no、is_current、origin_file_name、file_size、uploaded_by、uploaded_at。没有内容SHA256，也没有此路由的幂等请求参数。
4. GET /files/work-orders/{work_order_id}提供持久附件列表，包含历史记录。页面只显示指定分类/轮次且is_current为真的资料包。核对时必须区分“文件仍存在”和“文件仍是当前版本”。
5. GET /files/{file_id}/download可取得内容；文件名/字节数一致不能证明内容一致，严格核验应下载同一附件版本副本并校验SHA256。
6. 项目ID和工单ID是不同对象。不得从/projects/20/flow直接推定work_order_id=20。必须核对项目流程返回的current_work_order_id，或通过当前页面受信任适配建立关系。
7. 所查列表/下载路由只显式依赖当前登录用户，未在该路由函数中看到项目范围检查。不能据此枚举工单/附件或宣称完整RBAC已验收；本平台必须严格限制获准项目与精确附件。全应用权限需另查，不自动修改OA。
8. 网站认证使用localStorage中的access_token。平台Agent不应读取/转发该值，不通过抽取浏览器Token实现通用API代理；优先保留网站原生UI操作和下载流程。

## 3. 接入方案

- 浏览器核心保持通用；OA作为独立站点适配器，不将OA路由规则加入普通浏览器权限白名单。
- 写入前固定站点、项目唯一ID、真实工单ID、分类、轮次、文件SHA及当前槽位状态；原生确认展示“新增”或“替换当前版本”的实际效果。
- 槽位已有当前文件时，未取得替换授权必须停止，不得用测试上传使业务文件退为历史版本。
- 对未知上传先查询获准对象的持久状态；不自动调用上传/替换/删除/提交审核接口。
- 回执包含任务/操作ID、网站、项目/工单、附件ID/版本/分类/轮次、文件SHA、核验时间和验证方法。网站返回的storage_key不是必要交付数据，不传给模型。
- 原生下载或经独立授权的受控读取取得同一附件副本后，后台比对内容SHA。仅页面提示或模型提供的文本不足以生成成功回执。
- 保存成功、当前版本有效、正式提交审核是三个不同状态。只完成上传不得声称已提交审核或审核完成。
- 没有足够证据则保持unknown；保留本地防重标记。恢复界面只能发起只读核对，不能一键清空未知记录后重传。
- 若UI无法稳定提供版本及对象依据，再单列OA接口扩展申请；不得偷读凭据或绕过项目权限以迁就当前实现。

## 4. 待验收用例

1. 空槽位首次合成上传：持久记录与下载SHA一致，不触发提交审核。
2. 同名同大小但内容不同：不能误认作本轮成果。
3. 上传响应丢失但已保存：只读恢复成功，不产生第二版本。
4. 刷新/重启/取消后仍能定位原操作及对象，不依赖模型重新命名对象。
5. 同名项目、项目/工单ID不同、审核轮次不同：不能串对象或串版本。
6. 现存资料包无替换许可：提交前拒绝，原当前版本不变。
7. 文件已被后来版本替代或删除：明确报告历史/失效，不能显示当前交付完成。
8. 当前账号权限变化、登录失效、页面跳转：中止核验，不读取其他对象或暴露Token。

## 5. 下载回读的当前接线缺口

- 平台 `browser_observer.py` 的 `resolve_download` 只解析当前 link 的 HTTPS 地址；`NativeTaskDownload` 通过 `page.download()` 发起直接链接下载。
- `browser_download_controller.py` 此前只接受HTTP/HTTPS；本轮已增加当前HTTPS页面同源blob接收、保存框前后及交付阶段来源复核。任务侧须显式allow_blob许可，既有NativeTaskDownload尚未启用。
- OA `frontend/src/api/files.ts` 的下载函数先通过网站自身认证请求取得 blob，再创建临时链接触发下载。不能把新增来源哈希字段当作已经支持这一流程。
- 后续需为按钮触发下载建立一次性、当前页面/任务绑定的捕获窗口，保留本地保存确认、取消及接管门禁；blob 内嵌来源必须严格匹配可信 HTTPS 页面。不对所有 blob 或任意脚本开放下载。
- 来源页面键仅是上下文证据，不包含附件 ID、工单或版本。上述下载兼容性完成后，仍需独立绑定网站当前附件记录，核验下载内容 SHA；普通下载记录不得直接升级为上传成功回执。
- 必须补真实 WebEngine 按钮生成下载、跨源 blob 拒绝、来源变更/超时/重复下载、取消不交付及旧直接链接路径回归，再进入真实 OA 案例。
- 接收层验证：32项专项/邻近通过，含独立真实WebEngine合成HTTPS来源页面生成blob并核对文件内容、原整窗HTTP下载；不是实际TLS服务或OA端到端。Agent按钮动作、单次捕获关联以及持久文件记录对象绑定仍待实现。
