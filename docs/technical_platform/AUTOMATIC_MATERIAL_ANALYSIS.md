# 自动识别评估明细表资料

状态：源码已接入，EXE 已构建为 0.2.5；本次提交同步云端接口，部署结果以 Zeabur 与公网检查为准。

评估明细表入口不再要求用户手工选择科目余额表、序时账等角色。保留本轮读取、联网识别及生成副本的授权。客户端本地提取可见文本，经现有隐私过滤后，每个文件最多提交 6,000 字符节选；单轮最多 20 个文件。原件、路径和隐藏工作表不上传。

服务端新增 `POST /api/v1/material-analysis`，复用登录验证、模型路由、余额预留、计费及请求幂等。只返回经过结构校验的文件 ID、类型和判断依据，不返回费用、Token、API Key。识别结果不能指定外部文件或执行脚本。

有歧义、同类多文件、缺少范围依据时停止生成并反馈，不能把识别成功当作填报通过。现有确定性生成器仍只支持已实现的来源布局；模型识别不等于支持任意布局、混合类型工作簿或扫描件的自动填报。

无科目余额表和序时账：银行单资产、资产负债表及银行证据充分且核对通过时可生成；不伪造科目余额表。其他组合需进一步提供相关明细或扩展适配器，不强制所有用户提交同一组文件。

验证：新增自动分类 UI、任务授权、模型输出文件 ID 校验、可见内容传输、服务端计费调用与认证测试。合成银行场景仅提供资产负债表和银行资料，已完成源码及 EXE 生成与复核；10,123 条模板公式及实际超链接目标保留。未调用真实付费模型。
