# 金融数据云端部署

本次仅为最新主分支增加金融数据服务，保留现有Agent架构、登录保护、任务所有权和模型计费实现。旧本地候选客户端的金融HTTP接口保持兼容。未替换主分支的桌面客户端代码。

- 113个工具：103个Fuyao金融接口、6个宏观工具、4个辅助工具。
- 管理员在原总控配置一个共享API Key，使用既有加密密钥加密保存；普通用户不能读取。
- 自然语言选接口沿用原有模型计费；直接数据调用不新增收费规则。
- 迁移为 `0011_finance_data`，接在现有 `0010_billing_stream_lease` 后面，不能使用旧候选分支的 `0008_finance_data`。
- 财务接口、结果读取和取消均要求现有平台登录，结果按账号隔离。

## 上线顺序

1. 创建生产数据库备份。本次已在2026-10-20的Zeabur控制台确认备份记录生成；没有执行生产还原或宣称完成独立还原测试。
2. 沿用此前PR #12、#13的管理员合并流程，全部CI通过并处理自动审阅意见后再合并。保留现有分支保护和部署来源分支。
3. Zeabur服务的旧Dockerfile覆盖原来只复制服务端子目录，本次已同步为仓库 `deploy/report_review_server/Dockerfile` 的完整内容，确保 `finance_data`、共享契约及目录文件进入镜像。保留原数据库URL、JWT密钥、供应商加密密钥和单副本配置。
4. 使用最终真实提交号更新构建标识，避免现有旧环境变量把新镜像错误标记为历史提交。启动脚本先迁移至 `0011_finance_data`，迁移失败不得继续提供服务。
5. 核对health、capabilities中的 `finance_data: 1` 和真实提交号，再由管理员在总控录入共享Key。
6. 验证宏观查询、公司数据查询、普通账号权限和原收费记录。未配置Key时，公司数据不能视为已验收；不要把宏观源成功当作公司数据成功。

## 回退

保留新增金融表、已有账号和计费记录，以及原有加密密钥，回退应用镜像。存在金融配置或查询记录时，迁移拒绝破坏性降级，不通过清空记录来回退。

## 本地验证

基于主分支 `7d344715f89e5b34592851338866d5332ded8f2a`：服务端339项通过、1项跳过，4组总控脚本通过，仓库全量Ruff检查通过。测试使用隔离数据库和模拟付费上游，没有产生真实模型费用。
