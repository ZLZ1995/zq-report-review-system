# 生成后复核、差异处理与反馈

## 执行顺序

1. 记录原始来源文件及 SHA256；从本次明确提供的最新一期财务报表识别编制单位、期间。
2. 生成临时工作簿，保留模板公式、链接、结构和原交付文件。
3. 重新打开临时工作簿及来源文件，核对资产负债表本期/上期数、六大往来客商余额和漏项、序时账业务内容及发生日期。与写入记录比较仅是附加检查，不能替代原始资料复核。
4. 对具有唯一来源证据的合法输入格最多自动修正一轮，重新读取核对；涉及公式、汇总页、冲突来源或不明确映射时不自动修改。
5. 如公式结果没有有效缓存，必须取得可靠计算结果再验收。`--allow-excel-recalc` 使用独立 Excel 实例只读计算，不调用 Save/SaveAs；脚本仅更新临时工作簿公式缓存，并保留公式。没有计算环境或计算失败则反馈阻断，不能把未计算认作零或 OK。
6. 依次通过原始来源复核、公式保护、封面检查、平衡及分类差异检查、语义和结构检查、必需报告检查后，才原子替换交付文件。

## 证据映射及覆盖边界

`--source-checks` 接收 UTF-8 JSON 数组，任务配置对应 `source_checks`。每项指定原始 XLSX 的位置及目标位置，例如：

```json
[
  {"source":"D:/sources/raw.xlsx","source_sheet":"Sheet1","source_cell":"B5",
   "sheet":"银行存款","cell":"G6","kind":"amount"}
]
```

`kind` 为 `amount`、`date` 或 `text`；上述坐标仅为格式示例，必须按实际模板核实。金额误差阈值小于 0.005 元，来源空白或未计算不视为已验证。

目前自动重读覆盖支持布局的财务报表、六大往来余额来源和序时账；其他已填写明细字段需提供明确原始证据映射，否则标记 `source_unverified` 并阻断。不能把中间加工表冒充独立原始证据。PDF 对账单、纳税申报表尚不具备通用自动逐字段回核器，必须核对原文件页码/原文、记录证据并补充受测试的适配器；不能宣称 PDF 已自动复核通过。

六大往来按客商核对金额并检查来源遗漏；该检查不能代替逐原始明细行的溯源。复杂辅助维度或多行同客商应补充逐行映射。无法路由的非零来源行必须反馈，不能跳过。

## 差异处理

- 写入或列映射错误：唯一原始证据、非公式且合法输入格可自动修复一次；仍不一致则阻断。
- 借贷方向、客商、来源期间或金额冲突：记录两侧证据，回到来源解析及路由定位，不选一个数强行覆盖。
- 原始报表与余额资料不符：保留真实差额，要求企业说明或补充更正资料，不生成净额调整行、不删行凑平。
- 序时账无明确同客商、同科目、正确发生方向分录：业务内容/日期留空，备注“序时账未检出匹配分录”。按已获用户认可的缺失规则列入待补资料；已填写却无证据的字段必须阻断。
- 仅获准占位的固定资产等：保留占位和缺失资料说明，不宣称台账明细已核验。
- 来源在运行中变化、公式丢失、J4 未计算/非 OK、分类差额、余额不平、文件损坏：阻断交付，修正原因后重跑全部检查。

## 必需输出与用户反馈

- `source_recheck_report.json`：重新读取的来源证据、核对项、未通过项及覆盖边界。
- `automatic_repair_report.json`：有证据的修改记录及重新核对结果。
- `difference_resolution_report.json`：差异位置、来源位置、原始值、生成值、差额、处理要求和未解决状态。
- `completion_status.json`：`complete` 或 `blocked`，未解决数量及反馈标志。
- `user_feedback.md`：可直接向使用者说明的问题和待补材料。

最终回复必须说明是否生成正式成果、哪些问题已解决、哪些仍未解决及需要什么资料。存在阻断项时只提供核查报告/临时文件说明，不将临时文件称为已完成成果。主流程异常退出也必须尽可能生成反馈；不能仅打印堆栈或让使用者自己查 JSON。
