# ADR 0003：Context Manifest 与 Token 预算

- 状态：已接受（G03 实施）
- 日期：2026-09-18

## 背景

`context.build_context` 目前：取最近 6 条用户消息（各截 800 字符）+ 确认记忆（共 2500 字符预算），整轮渲染上限 12000 字符。它是有界的、带来源标注的，但：字符数不是 Token 预算；没有证据片段层（文件内容目前不进上下文，由服务端审核流程另行处理）；没有摘要层；没有可观察的"本次调用用了哪些来源"清单。

## 决定

1. 每次模型调用前构建并保存脱敏 `ContextManifest`：系统策略哈希、TurnEnvelope 哈希、Skill 版本/规则哈希、记忆 ID、摘要 ID、证据片段 ID、工具回执 ID、分段预算。
2. 分层预算顺序：系统红线（不可裁剪）→ 本轮 envelope（不可裁剪）→ 选中 Skill 契约 → 文件证据（目标优先于参考）→ 记忆（≤5 条）→ 会话摘要 → 工具回执（按引用，旧大输出落盘）。
3. 从字符裁剪升级为 Token 估算；每段保留来源、哈希和截断原因。
4. 摘要标记"非原始证据"，最终判断回查原片段。
5. Excel 证据入口复用并再次验证 hidden/veryHidden 过滤。
6. 用户诊断视图可说明来源，但不泄露系统提示词、价格、Token 明细或密钥。

## 替代方案

- 继续字符预算：拒绝，与模型实际计费/截断行为不一致。
- 整篇文档传入：拒绝，违背最小上下文和隐藏表红线。

## 后果

- 新增 `context_manifest.py`、`context_budget.py`、`conversation_compactor.py`、`evidence_retriever.py`（G03）。
- `context.py` 保留为兼容入口，内部改由 manifest 驱动。
- Manifest 落盘内容必须脱敏（只存 ID/哈希/预算，不存正文）。

## 验收

- G03：同一输入生成稳定 manifest；隐藏表片段进入 manifest 为 0；本轮范围与红线永不被裁剪；长会话 Token 显著下降且审核召回率不下降。
