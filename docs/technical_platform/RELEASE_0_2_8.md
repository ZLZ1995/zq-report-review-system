# ZQ Workspace 0.2.8 发布说明

## 身份与兼容范围

- 客户端版本：`0.2.8`
- 发布序号：`3`
- 本地数据架构：`11`（与 0.2.7 相同，无新增破坏性迁移）
- 服务协议：`1`
- 最低接管基线：先使用 0.2.7 托管接管包建立启动器/更新器布局；已处于托管布局的客户端可在线升级到 0.2.8。

## 本次修复

- 客户端执行资源从仅线程内计数改为跨客户端进程协调：Office 和同一输出目录保持单执行者，模型调用保持最多两个并发，等待任务仍可取消。
- 跨进程锁文件只保存资源标识摘要和槽位，不保存项目路径、客户资料或模型内容；异常建锁不会遗留假忙状态。
- 服务端修复同一 `client_request_id` 并发预占的唯一约束竞争，使幂等重放返回同一冻结记录；并发超额预占与重复结算仍保持单次扣款。
- GitHub Release 资产提升工作流按目标标签动态校验版本文件名，不再固定为 0.2.7，仍只允许提升指定成功 CI 的四项不可变产物。

## 验证摘要

- 客户端及技术平台完整回归：1126 passed。
- 跨进程资源专项：8 passed；资源锁/生成/浏览器循环/调度邻近：15 passed。
- 服务端完整回归：205 passed、1 skipped；真实 PostgreSQL 并发与隔离备份恢复演练通过。
- 应用更新继续使用 Ed25519 签名、包 SHA256、大小、协议和数据架构门禁；本版本仍未配置 Windows Authenticode，不把应用级签名表述为系统代码签名。

## 发布纪律

- 0.2.7 草稿未进入 stable；0.2.8 必须使用本说明对应的精确提交重建、签名、灰度和实机验证后才能激活稳定通道。
- 业务资料、历史项目和成果仍保存在用户选定的非系统盘项目目录，不随程序包上传或迁移到 C 盘。
