# ZQ 技术平台整合改造方案 V2

日期：2026-09-16。状态：规划，未实施、未打包、未部署。

跨客户端、GitHub、Zeabur的执行顺序、环境配置和可交给 /goal 的目标文本，见同目录 GOAL_INTEGRATED_DELIVERY_CHECKLIST.md；本文继续作为产品与安全设计依据。

需求修订：浏览器是独立通用功能，不与 OA 绑定。支持用户手动使用、Skill 声明调用和 Agent 理解自然语言后调用；新增经用户同意的网站账号密码保存与安全填充。OA 只是网站集成案例，不是浏览器启动、导航或登录的前置条件。

## 1. 方案关系与产品定位

本方案整合此前自然语言 Agent / Harness 改造与新增需求：在线更新、通用内置浏览器、网站凭据管理、Agent 浏览器操作、项目多分支及并行工作。

前版文件施工清单 NATURAL_LANGUAGE_AGENT_CONSTRUCTION_PLAN.md 中的安全红线及细项继续有效；本方案调整实施顺序并增加模块。旧 NL00—NL07 不能直接改标为新阶段已完成。上线前再按本方案建立逐项施工签收表。

产品定位：项目驱动的专业智能工作台。一个项目可承载多个独立或有来源关系的对话；Agent 理解目标后规划并调用专业 Skill、本地工具或通用浏览器/网站 API；Harness 统一负责权限、范围、资源调度、状态、计费、验证与追溯。浏览器可独立使用，不要求先运行任务；更新系统独立维护程序版本，不接管业务数据。

不把模型选择、Skill 选择、任务理解混为一谈；也不把内置网页、网页可操作、OA 深度业务整合视为同一完成状态。

## 3. 核心对象与界面

对象关系：账号 → 项目 → 会话/分支 → 任务 → 计划步骤 → 工具调用 → 验证后的成果。
关联对象：文件版本、待回答问题、授权、浏览器标签页租约、网站对象引用、凭据不透明引用、计费请求、程序版本。任务和对话不保存密码。

### 3.1 左中右布局

- 左侧：项目树；项目下可展开会话，支持新建、重命名、归档、未读提示、任务状态；从指定消息分支建立子会话。
- 中间：当前会话、流式回复、理解摘要、任务进度、待授权动作、成果入口；保留 Enter 发送、Alt+Enter 换行和拖拽上传。
- 右侧：文件 / 浏览器 / 记忆等面板标签；右上角统一“显示/隐藏侧边面板”按钮，支持拖动宽度及记忆布局。
- 浏览器支持地址栏、新标签页、前进、后退、刷新、书签、自定义主页、域名显示、登录凭据管理、用户接管和停止 Agent 操作；OA 可作为书签之一。
- 隐藏面板仅改变可见性，不自动退出网站、清空页面或取消任务；关闭标签页与隐藏面板分开处理。

### 3.2 Agent 与用户共同使用浏览器

三种入口共用同一个浏览器基础设施：用户手动打开并浏览任意正常网站；Skill 声明浏览器能力需求，由 Harness 检查权限；Agent 根据自然语言理解主动规划浏览器步骤，不要求用户选择 Skill。例如“登录 OA 上传本次生成的报告”“打开某网站查询资料”“登录供应商网站下载指定附件”。目标网站、账号或文件不明确时先追问，不猜测。

浏览器可以无活动任务独立使用。Agent 仅在任务需要时打开或关联标签页，展示用途和所属任务；不能因面板已打开便读取用户其他无关页面。网站登录不是所有任务的前置条件，不需要浏览器的本地任务不启动浏览器。

默认建议：首次操作自动显示相应页并简述用途；用户主动隐藏后不循环抢焦点，以状态徽标提示。写入前显示目标、动作、关键字段和确认入口。用户接管立即收回该标签页的 Agent 操作租约。

“自动打开网页”不等于“自动获得提交权限”；“面板隐藏”也不等于获得无人监督的后台写入权限。

## 4. 新增需求设计

### 4.1 联网更新：程序可替换，历史数据不可被安装器清理

先建立明确的数据边界：

| 区域 | 内容 | 更新行为 |
|---|---|---|
| 版本化程序目录 | EXE、依赖、内置工具及受版本管理的资源 | 下载新版本到独立目录，验证后切换 |
| 用户选定的数据目录 | 项目索引、会话、文件版本、成果、记忆、外部 Skill | 不覆盖、不删除、不因卸载默认清理 |
| 用户选定缓存目录 | 浏览器缓存、更新暂存、下载暂存 | 非系统盘、配额和清理规则；不得混放唯一业务副本 |
| 凭据存储 | 平台 refresh token、经同意保存的网站凭据 | 独立受保护存储，不写入更新包、对话或业务日志；同机升级保留 |

当前在旧程序目录下的数据需要一次性可校验迁移：识别真实路径 → 用户确认目标 → 复制并校验 → 切换索引 → 原目录暂保留。不能凭空假定现有客户的历史已经丢失，也不能移动整个宽泛目录。

更新闭环：检查版本 → 展示更新内容/兼容性 → 下载暂存 → 校验签名与哈希 → 等待任务安全结束和浏览器草稿处理 → 备份数据库 → 独立 updater 切换程序 → 执行版本化迁移 → 启动健康检查 → 成功确认/安全回退。

安全与兼容要求：

- HTTPS、包 SHA256、签名发布清单及内置可信公钥共同校验；仅哈希不足以证明包来自可信发布方。签名私钥不进入仓库、客户端或普通配置文件。
- 清单包含版本、平台架构、包 URL/大小/哈希、协议范围、数据 schema 兼容范围、最低更新器版本、签名 key ID 和更新内容；防止未授权降级及元数据重放。
- 发布下载源与重定向允许列表固定；下载重试/续传、磁盘不足、占用、断电、损坏包、路径穿越分别测试。
- 首期采用完整版本包在线替换，不先做二进制差分；增量更新不是首期安全交付前提。
- 无活动任务时提示安装；执行中可下载但不切换，不强杀 Office/WPS，也不销毁任何网站的未提交草稿。
- 保留上一稳定程序版本。新数据库不兼容旧版时，不直接换回旧 EXE 强开新库；迁移失败优先恢复迁移前一致备份。上线后已有新写入时，需兼容迁移或明确恢复流程，不能静默丢弃新数据。
- 下载缓存和业务数据不得默认占用 C 盘；安装位置和数据位置独立。
- 内置 Skill 随受签名的兼容版本发布；用户外部包不被覆盖。活跃任务固定规则及模板版本，不能执行中热替换。
- 发布功能纳入独立总控服务台，具备管理员授权、渠道、撤回、审计和灰度；CI/独立签名流程保管私钥。

首次获得在线更新器可能仍需安装一次过渡版本；升级过程须保留现有数据。以后正常更新不要求用户卸载重装。

### 4.2 通用内置浏览器：独立基础能力，网站集成可插拔

优先以当前 PySide6 + QWebEngineView 做技术验证，复用桌面架构；只有在兼容、体积、性能、部署或自动化验证不达标时再评估 WebView2 等替代方案，不预先整体重写桌面。

验证清单：当前 PySide6 版本与 WebEngine 包兼容、普通网站及 SPA 登录、多步骤登录、跳转/弹窗、Cookie/localStorage、验证码/二次认证、PDF/附件预览、下载、打印、缩放、中文输入、页面断网恢复、浏览器子进程崩溃及 EXE 打包。OA 是测试站点之一，还必须验证非 OA 网站。不得关闭证书校验、沙箱或网页安全策略来“跑通”；不能假定嵌入 WebEngine 就自带完整密码管理器。

浏览器 Profile 按平台账号和使用环境隔离，网站之间遵循浏览器同源隔离；缓存和持久目录在用户选定数据根目录下，不使用未经配置的系统盘默认路径。平台账号切换关闭或锁定前一账号页面和凭据访问。网站账号与平台账号不视为同一身份；同一 Profile 的标签可共享该网站登录态，任务操作租约仍独立。

使用各网站原登录流程。首次登录用户手动输入；经同意保存后可由本地可信组件填充，详见 4.5。Agent 不读取密码框、Cookie、Token、localStorage 凭据，也不绕过验证码。网站单点登录属于可选适配，不是浏览器基础依赖；不得硬拷贝登录令牌。

支持普通互联网浏览，不把导航硬编码为 OA 域名白名单。用户手动导航与 Agent 自动化权限分开：Agent 访问范围绑定当前任务，跨站且扩大业务范围时重新确认；新域名本身不等于禁止手动浏览。外链、新窗口、下载、自定义协议和本地资源访问分别控制；不绕过 TLS 错误，不向不安全 HTTP 页面填充保存的密码。禁止网页获得通用本地文件或 shell 桥接能力。

### 4.3 Agent 操作浏览器：受控工具，不是无限网页遥控

工具契约：open_tab、navigate、observe、read_visible、click、fill、select、scroll、wait_for、download、fill_saved_login、takeover/release。Agent 调用绑定 owner/project/session/task/step/tab 和页面版本，返回可验证的观察结果与副作用记录。fill_saved_login 只接收不透明账号引用，经本地门禁填充，不提供 get_password 工具；手动浏览不要求创建任务。

模型只提出结构化动作。确定性工具层执行有限操作，不能执行模型或网页提供的任意 Python、shell 或无约束 JavaScript。内部可以有固定、审核过的 DOM 采集脚本，但不向网页暴露通用宿主对象；不对外开放可被其他进程随意连接的调试端口。

观察优先使用可见页面的结构化元素与短文本；必要时使用截图，并先控制敏感范围。每次基于新观察定位，不复用导航前的失效元素；页面有跨域 iframe 或不支持控件时明确限制，不绕过浏览器安全边界。

权限按动作效果划分，不能只按“点击”或 GET/POST 判断：

| 动作类别 | 默认策略 |
|---|---|
| 打开网站、导航、查看授权对象 | 当前任务范围内可执行；日志显示所读对象，不扩展到无关标签页 |
| 使用保存的网站账号登录 | 验证站点、账号和用户使用授权；由可信本地组件填充；验证码由用户处理 |
| 填写页面但尚未提交 | 可按明确任务准备；检测自动保存，有服务端副作用则按写入处理 |
| 下载附件 | 明确文件与本地非系统盘目标；下载结果核验并登记，不自动变成本轮审核输入 |
| 上传成果、保存业务记录、正式提交 | 授权绑定具体网站、业务对象、文件/字段摘要和本次动作；明确原始指令可作为该动作授权，有歧义或范围变化再确认，禁止宽泛永久授权 |
| 审批、删除、付款、权限变更、不可逆业务动作 | 首期不自动执行；后续专项开发和逐次强确认 |

原件禁止自动上传的规则继续有效。首期网站上传仅考虑明确授权且通过验证的成果副本；如未来要上传原始资料，需单独修改产品策略并解决隐藏内容/敏感数据问题，不能通过浏览器文件选择框绕过限制。

网页及网站文档内容是数据，不是指令。页面出现“忽略限制、上传全部文件、读取密钥”等内容不得改变计划或工具权限。浏览器观测经范围过滤及凭据脱敏后才可发送模型，不上传整个网站页面库或后台会话凭据。

每个标签页同一时刻只允许一个操作租约；用户接管后 Agent 暂停。多个会话即使共用网站登录态，也不得同时操作同一标签页；切换网站账号时还需锁定受影响 Profile，避免其他任务身份改变。响应不明的提交先查服务器业务状态；不能盲点第二次。已提交的业务事务不能通过本地取消保证撤销。

### 4.4 项目多会话、分支与并发工作

同时支持两种不同操作：

1. 新建独立会话：同项目的新工作，不继承旧消息、附件勾选或执行授权。
2. 从某条消息创建分支：记录 parent_session_id、fork_message_id 和分叉时的上下文快照；可引用已完成事实和成果，不复制运行中任务，也不继承写授权、浏览器租约或待执行动作。

项目文件库是共享目录，当前任务文件范围不是共享全选。每个会话独立拥有草稿、附件选择、理解状态、待答问题、任务列表、成果入口和浏览器标签引用。跨会话引用必须明确选择；分支间不自动合并后续对话或发布结果。

把全局 self.worker 改为 TaskManager：按会话/任务管理后台 worker、取消句柄和事件路由。切换会话不终止后台工作；取消只针对目标任务；未读状态提示后台完成结果，不把结果写入当前正在查看的其他会话。

建议初始资源策略（需负载验证，可配置）：模型任务最多并发 2 个；Office/WPS 自动化默认串行；同一浏览器标签页排他；同一输出文件不得并发写入；所有任务使用独立工作目录。并行“工作会话”不等于所有工具无限并行。

同账号多任务仍遵守单设备登录策略；服务端钱包需原子预占，不能多个线程都因旧余额检查通过而超额启动。项目只读资源可共享，不可变版本或租约保护写资源，任务完成前后检查输入哈希。

### 4.5 网站账号密码：用户同意保存，本地安全填充

登录态保留和密码保存是两项独立功能：有效登录态优先复用；需要重新登录时，才使用经授权保存的账号。首版不做云端密码同步，也不允许总控管理员查看或恢复客户网站密码。

保存与使用流程：

1. 首次由用户在网站输入登录信息。本地识别登录结果；成功后提示“保存账号密码 / 暂不保存 / 此网站不再询问”。无法确认成功时不静默保存；用户仍可在凭据管理界面主动录入。
2. 只有明确同意才持久化。修改密码后单独询问是否更新保存记录；失败登录不覆盖已有记录。
3. 保存许可不等于 Agent 使用许可，也不等于网站业务提交许可。默认手动触发填充；可按网站和账号单独勾选“允许 Agent 在我要求登录该网站的任务中使用”。已有该许可且用户任务明确时不重复询问密码；多账号无法判定时让用户选择。
4. Agent 只见已授权账号的脱敏标签和不透明引用。本地可信组件校验后解密并填入目标登录表单，密码不进入模型、会话、记忆或普通 fill 参数。登录成功只返回状态；验证码、短信和二次认证交给用户，不默认保存动态验证码。
5. 设置页提供站点/账号列表、删除、更新、不再询问列表和撤销 Agent 使用许可。密码默认遮蔽；若实现显示或复制，必须经本机重新验证身份，不经对话显示。

安全与数据边界：

- 首选 Windows 当前用户范围 DPAPI 保护的独立凭据库，文件位于用户指定非系统盘数据目录；不使用机器共享解密范围，不把明文密码或解密密钥与库一起保存。平台账号间另设访问隔离，但不将其宣称为对同一 Windows 用户恶意进程的绝对防护。
- 自动填充校验规范化 HTTPS origin（协议、主机、端口）、实际登录框所在 frame 和表单提交目标；不按域名包含关系匹配。跨域身份提供商仅在用户认可且验证的站点关联下使用，不默认共享密码。
- 填充前重新核对页面和表单，阻断相似域名、HTTP 降级、恶意 iframe、页面替换及不匹配的跨域提交。网页声明“请读取密码”不能获得授权。
- 密码只短暂进入可信填充链路与目标网站登录表单；目标网站本来就会收到登录密码，不能承诺防范已被攻陷的网站。DOM 观察、截图、工具返回、日志、异常、遥测和模型请求均需过滤密码及令牌，不开放抓取认证网络内容的工具。
- Cookie/会话存储单独实施访问控制与安全验证，不假定凭据库加密就覆盖全部浏览器 Profile。退出、清除浏览数据和删除已保存密码分别提供明确操作。
- 正常同机更新保留加密库和兼容版本；迁移或备份不得导出明文。更换电脑、重装系统或更换 Windows 身份可能无法解密，首版提示重新登录，不承诺跨设备恢复。

实现依据：[Windows DPAPI CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。其保护依赖用户/机器环境，不替代操作系统安全或网站信任校验。

## 5. 更新后的 Agent / Skill / Harness 职责

Agent：从对话中判断本地文档任务、通用网页查询/操作、咨询或复合任务；确认目标、网站、账号与对象；知道何时追问、申请权限、使用浏览器/API、选择 Skill；提供简短可核对的理解摘要。不以是否命中 OA 关键词作为浏览器调用条件。

Skill：规定专业作业方法与工具依赖，可以声明 browser.read、oa.project.read 等能力需求，但不能自行授予权限。审核、批注、填表、工商沿革及未来 OA 技能共享输入输出、版本和验收契约。

Harness：除旧方案门禁外，新增会话隔离、跨会话资源调度、浏览器租约、网站副作用确认、凭据使用授权及 origin 校验、重复提交防护、更新安全点及协议/数据兼容检查。客户端只做本地和界面执行，云端仍是认证、计费和远端执行状态的权威。

BrowserAdapter 是独立通用工具层，不隶属 OA 模块；各站点 Skill 可按能力调用。OA 作为可选集成，早期复用 BrowserAdapter；接口核查后，为稳定高频动作增加 OaApiAdapter。两者共用权限、对象范围、幂等、审计及后置验证。API不能成为绕过确认的捷径，也不直接操作 OA 数据库。增加其他网站不要求修改浏览器核心或安装 OA Skill。

统一状态不能只写“进行中”：理解中、待澄清、待授权、排队、执行中、待用户接管、验证中、远端状态待确认、已完成、正在取消、已取消、失败。更新待安装是应用维护状态，不混入某一业务会话。

## 8. 验收矩阵与关键场景

### 8.1 自然语言与会话

- 保留前版至少100条基础语义用例及独立留出集；加入“仅查看OA不要提交”“把当前会话结果准备成OA附件”“在另一个分支继续讨论”等案例。
- 明确意图、目标文件/网站对象、排除范围、是否需要授权及预期成果均纳入评分，不能只统计Skill选择命中率；包含未安装OA Skill时的其他网站任务。
- 至少三个会话交替操作，两个后台任务运行，取消一个不影响另一个；完成结果准确回到各自会话。
- 从历史消息分支不继承未完成执行、文件写入许可或审批；后续修改不反向污染父会话。

### 8.2 在线更新

- 使用包含多个项目、分支、消息、附件、记忆和外部Skill的合成旧数据，完成 N→N+1→N+2；逐项比对业务记录和附件哈希。
- 下载中断、磁盘不足、伪造签名、错误架构、解压越界、文件占用、迁移中断和新进程启动失败均可明确恢复。
- 活动任务、Office计算和网站未提交草稿存在时不强制重启；恢复后账单和任务状态可核对；同机升级后已保存凭据仍可安全使用。
- 更新失败不清空用户数据；成功后清理暂存不误删项目目录，保留规定数量的可回退程序版本。

### 8.3 通用浏览器、凭据与网站集成

- 不配置OA、不运行Skill也可手动打开非OA网站；自然语言和Skill均可触发浏览器；默认新标签页，显示/隐藏不丢页面状态；平台账号切换不串网站页面。
- 保存、暂不保存、不再询问、更新、删除、撤销使用授权、多账号选择均可验证；拒绝保存不落库，失败登录不覆盖密码；二次验证交给用户。
- 验证可信填充复用流程、同机更新保留、跨平台账号隔离；其他Windows身份无法解密时清楚提示重新登录，不输出密文或明文调试数据。
- 相似域名、恶意iframe、跨域表单、不安全HTTP、页面替换均不能套用保存密码；模型请求、DOM、截图、日志和异常不得泄漏密码/Token。
- 前端页面、API请求、外链、新窗口、下载和文件上传分别做策略测试；Cookie/Token不出现在模型请求或日志。
- 恶意页面指令不能索取本地密钥/全项目资料；超出任务授权的网站操作、隐藏敏感内容和跨项目读取不能放行；不得把正常手动浏览新网站误判为越权。
- 对测试OA记录执行受控操作；成功以服务端业务回执或可核验状态为准，不以按钮点击成功为准。超时后先查询，不重复提交。
- 人工接管、关标签页、网络断开、页面刷新及浏览器子进程崩溃都能停止失效动作且不拖垮桌面程序。

### 8.4 原有业务与发布

- 原件、锁定模板、Excel链接/公式/宏/隐藏状态不受新增浏览器和更新器影响。
- Office、WPS、二者并存、均未安装及中文输入法分别测试；只对实际需要Office计算的能力设置依赖门禁。
- 真实模型与OA写入联调使用经确认测试账号、脱敏数据、允许动作及费用上限；不把正式审批/付款当测试。
- 密钥泄露、原件越权写入、隐藏内容外发、跨账号/会话串用、未确认业务提交和重复扣费/重复提交均为发布阻断项。
- 新旧客户端、服务器协议、数据schema、内置Skill和浏览器组件版本组成兼容矩阵；不兼容时清楚提示，不伪报网络错误。

## 9. 建议的首版默认值与待确认项

以下是方案建议，不作为已取得的高风险操作授权：

1. 在线更新：自动检查；用户确认后安装；运行中不强制退出。下载是否自动可配置，默认手动开始。
2. 浏览器：首期即为独立通用浏览器；默认新标签页，OA仅为可选书签或集成，不作为浏览范围白名单。
3. 身份与凭据：保留各网站原登录；明确同意才保存本地加密密码，Agent使用另有按站点/账号授权；验证码由用户处理。不默认做跨站SSO，不提升网站权限，不做云端密码同步。
4. 并发：模型任务初始2个，Office/WPS串行，每标签页独占；最终以实际服务器/客户电脑压测确定。
5. 业务写入：准备和正式提交分开；审批、删除、付款、权限变更不纳入首期自动操作。
6. 首个OA闭环：建议从“查询项目资料，准备并经确认上传成果副本”开始；是否开放上传、目标模块和测试账号需实施前确认。
7. 分支：同时提供独立新会话和从历史消息分叉，不默认自动合并。
