## 第一小轮：统一 TaskSpec

保留现有固定审核流程，不在本轮引入自由工具执行。
TaskSpec 保存：schema_version、task_id、owner、project_id、session_id、user_request、
selected_files（ID/版本/哈希）、skill_id/version/rules_hash、model、permissions、acceptance_gates。
取代 app.submit 中散落的快照拼装，历史任务以显式适配器读取，禁止将缺省值误认成已确认授权。

## 第二小轮：上下文构建

从当前账号/项目/会话检索历史；仅传递相关且有限量的历史，不直接复制完整 SQLite 数据。
当前用户要求与历史内容、文件证据分开；工具输出/文件内容不可变成新权限。
明确确认的项目偏好通过筛选后注入，记录命中 ID 及正文版本；删除后后续任务不再使用。
缺少前轮结果或历史文件版本时要明确说明，不捏造连续审核上下文。

## 第三小轮：执行与 Harness 适配

通过统一执行入口调用现有 read-only preflight / review adapter。
复用旧 Planner / Harness 的接口思想及可测组件，不直接启用旧本地 API Key 调用方式。
权限核验、可见性门禁、幂等任务 ID、任务状态、文件哈希验收必须保留。
明确区分上下文组装、规划、执行、校验失败，返回可诊断事件。

## 每小轮验收

先失败测试再实现；覆盖当前要求优先、跨账号/项目隔离、记忆撤回、上下文限量、
隐私过滤、只读约束、旧快照恢复、取消及错误路径。每小轮回归通过才进入下一小轮。
费用预算未授权时全部使用假模型；真实验收单独记录，不以假模型测试替代。

## 第二阶段加固轮

- 任务领取改为 SQLite 写事务中的归属检查、状态变更和事件记录；同一任务只允许一个
  执行器从 queued 进入 running。领取失败不进入执行失败处理，避免误伤正在运行的任务。
- TaskWorker 不再重复修改失败状态，由 Harness 负责其已领取任务的状态；原预检入口
  默认也使用原子领取，Harness 调用时显式标识已领取，保留既有只读及可见性校验。
- 历史去重改为数据库比较完整文本，而非比较截取的 800 字符前缀，仍保持有界读取。
- 测试先行：领取接口缺失的两项测试先失败；长要求误删历史的测试确认失败后修复。
  平台 59 项通过，包含双线程领取、跨账号拒绝、终态拒绝、执行中重复进入不误伤回归。
  本轮不引入任务租约、进程崩溃后自动恢复或任意工具执行，这些不应由领取锁替代。

## 失败诊断展示验收轮

处理建议及任务编号。历史失败未记录阶段时明确显示未记录，不猜测根因。

避免把潜在密钥、响应正文等带入会话；不改变原有服务端计费、认证或审核逻辑。
