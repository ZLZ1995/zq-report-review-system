# Office Workflow to Skill

把不熟悉 AI 或技术规范的使用者带过“讲清工作方式、确认规则、生成技能、真实试跑”全过程。面向使用者使用中文业务语言，不要求对方编写 YAML、脚本或提示词。

## 边界

- 用于把可重复的办公流程制作成新 skill，或更新已有的同类 skill。
- 如果用户只是要完成一次 Word、Excel、PPT 或 PDF 任务，直接转交相应办公技能，不创建 skill。
- 一个 skill 只覆盖一个稳定工作目标。不同触发条件、输入、产物或验收标准明显不同的流程应拆分。
- 如果仓库已有高度重合的 skill，优先更新它；先说明复用与差异，避免重复创建。

## 工作流程

### 1. 识别用户真正的工作流

先阅读 [访谈指南](references/interview-guide.md)。每轮只问一个关键问题，最多两个；优先让用户上传一个真实样例、空白模板或已完成结果。对方回答后，用一两句话复述已确认内容，再问下一项。

不要一开始索要完整需求文档。不要询问“schema、frontmatter、API、脚本参数”等技术词。把问题改成日常说法，例如“每次开始时你通常会收到哪些文件？”“什么样的结果你会认为可以直接交付？”

### 2. 建立工作流契约

按 [工作流契约](references/workflow-contract.md) 整理：目标、触发方式、输入、来源优先级、步骤、判断分支、人工确认点、异常处理、输出、命名与保存位置、验收标准、样例任务和办公技能路由。

必须区分：

- 用户明确说明的规则；
- 从样例中观察到、仍需确认的推断；
- 尚缺失、会改变结果的决定。

只要存在会实质改变结果的未决项，就继续询问，不进入技能创建。信息不足、文件缺失、格式无法识别或规则冲突时，主动指出具体问题，并请用户决定处理方式；不得停住不反馈，也不得自行编造业务规则。

### 3. 让用户确认

用简洁中文展示契约摘要，至少包含“输入是什么、怎么处理、遇到例外怎么办、输出什么、怎样算完成”。明确询问用户是否按该版本制作 skill。

只有用户确认后，才把契约中的 `confirmation.workflow_confirmed` 和 `confirmation.ready_to_build` 设为 `true`。运行：

```bash
python scripts/validate_workflow_contract.py --contract <contract.json> --output <validation.json>
```

校验返回 `needs_user_input` 时，按报告里的 `questions` 继续询问。不得绕过确认状态。

### 4. 编排办公技能

按 [办公技能路由](references/office-skill-routing.md) 选择最少且足够的技能。先读本次会调用的每个技能的完整 `SKILL.md`，并遵守其引用的必要资源。

- DOCX、Word 文案与正式报告：`documents`
- XLSX、XLS、CSV、TSV 的填报、生成、分析：`spreadsheets`
- PPT、PPTX 与演示文稿：`presentations`
- PDF 的读取、抽取、生成、表单或版式核验：`pdf`

混合流程按“来源读取 -> 结构化处理 -> 目标产物生成 -> 目标产物验收”的顺序组合。PDF 或图片是来源、DOCX 是产物时，读取与版面核对交给 PDF/视觉能力，报告生成与最终渲染交给 documents。不要把办公技能的全部细节复制进新 skill；在新 skill 中写清调用条件、交接数据和验收证据。

### 5. 生成正式 skill

工作流契约通过校验后，使用 `skill-creator` 创建或更新目标 skill。遵守以下约束：

- 名称使用小写英文、数字和连字符，语义具体；
- `SKILL.md` 保持精炼，详细规则放入 `references/`；
- 重复、确定性的处理或校验放入 `scripts/`；
- 模板、示例和可复用文件放入 `assets/`；
- 如仓库运行时需要，提供 `skill.manifest.yaml`；
- 提供 `agents/openai.yaml`，默认允许自动触发；
- 写明正常路径、分支、异常时向用户询问的方式，以及可验证的完成标准。

### 6. 用真实样例试跑

至少完成一次代表性样例任务。没有样例时，先请用户提供；如果用户明确同意使用合成样例，必须标记其只能验证流程结构，不能证明业务规则正确。

试跑时调用相应办公技能，并完成其强制验收：

- Word：渲染并逐页检查最终 DOCX；
- Excel：重算、检查关键值和公式、扫描错误并渲染相关工作表；
- PPT：检查页数、内容、模板一致性、可编辑性并渲染全部幻灯片；
- PDF：重新打开，抽取或结构检查，并渲染逐页检查。

混合产物分别验收。只成功生成文件，不代表试跑通过。

### 7. 交付

向用户提供：

- 新建或更新的 skill 路径；
- 已确认工作流摘要；
- 调用的办公技能及各自职责；
- 试跑样例、通过的检查和仍存在的限制；
- 后续可直接触发该 skill 的自然语言示例。

不要把内部构建文件当成交付件。任何未完成的强制验收必须明确说明，不得声称 skill 已验证完成。
